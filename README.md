# Менеджер коллекции пользователей

Консольное приложение на Java 21 для итогового домашнего задания, уровни 1 и 3.
Хранит пользователей в `List<User>` (`ArrayList`), загружает TXT, обрабатывает данные
через Stream API и демонстрирует собственные сортировки с Generics и полиморфизмом.

## Сборка и запуск

Требуются JDK 21 или новее и Maven 3.9+. Команды выполняются из корня проекта.

```shell
mvn clean verify
java -jar target/java-collection-manager-1.0-SNAPSHOT.jar
```

## Меню

1. Добавить пользователя: ID, имя, email. При ошибке ввод пользователя повторяется целиком.
2. Загрузить пользователей: введите путь без кавычек, например `data/users.txt`.
3. Показать всех пользователей в порядке добавления.
4. Ввести подстроку имени: `filter()` ищет без учёта регистра, `sorted()` сортирует
   по имени и ID, `map()` извлекает email. Пустой запрос выбирает всех.
5. Выбрать вставки или слияние, затем возрастание или убывание имени.
0. Завершить программу. Конец ввода также корректно завершает работу.

Сортировки и Stream-обработка сохраняют исходный порядок коллекции. При равных
именах без учёта регистра сравниваются ID; убывание обращает весь компаратор.
Имена сравниваются через `String.CASE_INSENSITIVE_ORDER`, без языковой сортировки.
Пользователи хранятся в памяти текущего запуска; автоматическое сохранение не предусмотрено.

## Формат файла

TXT в UTF-8 без BOM, без заголовка, одна запись на строку:

```text
1;Анна Петрова;anna@example.com
2;Борис Иванов;boris@example.com
```

Пример: [data/users.txt](data/users.txt). ID — положительное число типа `long`,
уникальное во всей текущей коллекции. Имя обязательно. Email содержит ровно один `@`,
непустые части до и после него и не содержит пробелов. Повторяющиеся email разрешены.
Пробелы по краям полей удаляются. Разделитель `;` и переносы строк внутри полей запрещены.
Те же правила действуют при ручном вводе.

Пустые строки пропускаются. Ошибочная запись выводится с номером строки и причиной,
загрузка продолжается. При повторной загрузке существующие ID отклоняются.
В конце выводится число добавленных и отклонённых записей. Ошибка открытия или чтения
файла возвращает управление меню; ранее добавленные записи сохраняются.

## Тесты

JUnit 5 проверяет валидацию, дубликаты, UTF-8, ошибочные строки и ошибки чтения,
Stream-обработку, сортировки в обоих направлениях, стабильность, работу с Integer,
неизменность исходных данных, сценарий меню и завершение ввода на разных шагах.
